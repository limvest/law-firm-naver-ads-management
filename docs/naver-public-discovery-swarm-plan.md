# 네이버 공개 검색 기반 수집망 확장 PLAN

## 목표

기존 DB 사건명을 검색 seed로 사용해 네이버에 노출되는 법률 피해구제 페이지를 찾고, 그 사이트에서 신규 사건명과 관측정보를 수집한다. 신규 사건명은 다시 검색 seed가 되어 수집망을 순환적으로 확장한다.

## 수집 흐름

1. DB에서 관측 근거가 있는 사건명을 증분 seed로 선택한다.
2. `{사건명} 사기 피해` 변형을 네이버 공개 통합검색 HTML로 조회한다.
3. 광고·일반결과의 제목, 설명, 노출 순위, URL, 최종 랜딩 URL을 먱등 원장에 기록한다.
4. 랜딩페이지를 방문해 법무법인·법률사무소의 피해구제 광고/사건 상세페이지인지 판정한다.
5. 제목·H1·본문·URL·내부링크에서 사건명과 구체적 관측정보 후보를 추출한다.
6. 소스를 `상세정보 수집원`, `키워드 전용`, `보조 증거`, `제외`로 분류한다.
7. 중복·일반명사·법무법인명·확인되지 않은 단정을 제거한다.
8. Agent 3 품질 보고와 사람 승인 후에만 Agent 1·2가 DB 반영과 수집 규칙 적용을 수행한다.

## 운영 가드

- 네이버 검색 API는 사용하지 않는다.
- `NAVER_PUBLIC_SEARCH_ENABLED=1`일 때만 실제 검색한다.
- 기본값은 DB 쓰기 없는 dry-run이다.
- CAPTCHA, HTTP 403, HTTP 429를 발견하면 즉시 중단하고 우회하지 않는다.
- 동시성은 처음 3개 이하로 제한하고 요청 간격을 준다.
- Luna worker는 구조화 판정만 생성하고 키워드를 직접 발행하지 못한다.
- 대상 사이트의 공개 페이지만 조회하고 인증·차단·캡차를 우회하지 않는다.

## 1차 통과 기준

- 실제 검색 응답 성공률 95% 이상
- 원장의 동일 검색결과 중복 0건
- 법무법인명을 사건명으로 오인한 건수 0건
- 사람 표본 검토 정확도 90% 이상
- CAPTCHA/403/429 발생 시 안전 중단
- 운영 키워드 DB는 별도 승인 전까지 무변경
